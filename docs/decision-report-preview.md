# GoEast P1 Preview handoff

## What is ready to inspect

- Public synthetic example: `/examples/iching-decision-report`.
- Preview-only synthetic walkthrough: `/examples/iching-decision-report/walkthrough`. It does not authenticate, generate a real report, call a provider, or touch a GoEast database. Do not count it as conversion or hosted TEST checkout verification.
- Real offer is disabled by default. The existing free cast and monthly Pro paths are separate. P1 base price is USD 1.99 (199 cents), one payment/no renewal. No live checkout path is enabled by this branch.

## Owner-bound acceptance, only if isolated settings are authorized

1. Provision a separate empty QA Supabase project. Do not apply migrations to GoEast's current Preview/production Supabase project. Apply `supabase/decision-report-isolated/001.sql` only to the QA project; it is intentionally outside the regular migration chain and refuses the existing app's table footprint. Use synthetic inputs and the designated QA UUID. Existing Supabase session authentication identifies the owner, but private P1 data uses only the separate service URL/key. No open public roles or user-scoped API connections are used for these tables.
2. Set Preview-only `DECISION_REPORT_SUPABASE_URL`, `DECISION_REPORT_SUPABASE_SERVICE_ROLE_KEY`, `DECISION_REPORT_PREVIEW_QA_USER_ID`, `DECISION_REPORT_MODE=mock`, and `DECISION_REPORT_ENABLED=true`. The authenticated mock mode explicitly labels payment/refund actions, persists/deduplicates an order, and uses deterministic simulated generation. It never reaches Creem or Azure.
3. TEST provider acceptance is separate. Check that the dedicated provider TEST product is one time, active, USD 199 cents, and different from Pro; do not use a LIVE product. Set Preview-only `DECISION_REPORT_MODE=test`, `DECISION_REPORT_CREEM_API_KEY` (TEST key only), `DECISION_REPORT_CREEM_PRODUCT_ID`, `DECISION_REPORT_CREEM_WEBHOOK_SECRET` (separate from P0), and `DECISION_REPORT_PREVIEW_ORIGIN` (exact Preview alias). Wire TEST callback to `/api/decision-report/webhook`, not the subscription webhook. Existing Azure variables can drive the TEST report review when separately authorized. Optional `DECISION_REPORT_AI_MODEL` overrides the model; generation requests cap completion at 1,600 tokens and 25 seconds, with no SDK retries. Costs and exact gateway model price are not measured by the synthetic run. Disable by removing `DECISION_REPORT_ENABLED` and redeploying the Preview. Do not promote this branch or change production flags/SKU/prices.
4. Use one designated QA user and a synthetic career question. Cast once, inspect the quote and the six lines, cancel via Back without entitlement, then resume the same pending checkout. Confirm an authorized TEST payment remains TEST and cannot alter Pro. Reload, generate, verify the exact same question/lines and asset, save an action note, reopen through Account or Consult history, confirm another account cannot open it. Verify a full accepted refund with a captured sanitized TEST payload revokes access only to the P1 artifact, and re-delivery of late paid notification cannot grant it again. Reload or force one mocked generation failure and verify the same order can be retried without another charge. Partial/unknown refund is not silently treated as full.
5. Record provider evidence separately. Official Creem examples are not an observed one-time TEST webhook. Validate checkout creation URL and effective terms, signature, provider entity IDs and refund totals in the isolated TEST run before considering any real deployment. Provider `request_id` is stable but is not proof of retry idempotency. An ambiguous provider or persistence outcome leaves an order on hold rather than creating a second checkout. Only reconcile by verified provider checkout/order and that request ID; never delete the claim while payment status is uncertain. No automatic provider retry behavior is claimed.

## Data and telemetry

- Owned by verified auth UUID; one durable order and independently identified artifact per unchanged question/cast and test mode. Unchanged repeated requests reuse the pending checkout or report. A report snapshot cannot be delivered until provider-confirmed payment (or explicit mock pay for the isolated QA path). Captured lines and source are resolved independently of the model, and only delivered reports expose private content.
- New events use `offer_id=decision_once`: `offer_viewed`, `checkout_started`, `checkout_created`, `payment_confirmed`, `delivery_succeeded`, `delivery_failed`, `refund_confirmed`. The merchant/provider IDs needed for reconciliation are opaque; no question/body, email, private URL, or account ID is logged. Server P1 events are tagged as QA and test/mock; internal diagnostic warnings are not payment. Unlinked refund tombstones are not counted.
- [Creem checkout contract](https://docs.creem.io/api-reference/endpoint/create-checkout), [webhook payloads](https://docs.creem.io/code/webhooks), [transaction contract](https://docs.creem.io/api-reference/endpoint/get-transaction).
- Local SQL fixtures (no network or app database): install `@electric-sql/pglite@0.5.17` with a disposable npm prefix, then run `PGLITE_MODULE=/absolute/prefix/node_modules/@electric-sql/pglite/dist/index.js node scripts/verify-decision-order-sql.mjs`. Run application tests with `npm test`.
