# Shanghai Arrival Check: fulfillment integration

Scope: fixed, fictional trips in a branch-only rehearsal; no production database, customer mail, or live charge.

1. Persist a quote and frozen itinerary before creating a checkout. Correlate the Creem Test checkout to its own order and bind product, price/currency and provider order ID. Do not use a redirect or mailbox message as payment evidence.
2. Accept a verified raw-body Creem webhook. One transactional transition marks the order paid and makes it visible in the durable operator queue. Redelivery is safe. Quoted deadline does not reset. Refunds and disputes require rechecking the provider before sending.
3. Send a short, fixed internal notification containing only the opaque order ID; wake Emma from Gmail with an exact sender and subject filter. Store notification status independently of paid status; reserve work atomically, use the same idempotency key after transport ambiguity, and keep unnotified orders visible for a queue sweep.
4. Emma first reads the canonical scoped paid record, then researches the operating airline, Shanghai Airport and actual hotel. Verify terminal, property and what changes for the traveler (e.g. late arrival, no data or no usable payment). If missing or contradictory, hold for review rather than invent. Generate an offline personalized PDF with sources and bilingual address, then independently approve the exact version. First five live orders would require human review; no customer send is enabled in this branch.
5. Acceptance: signed success, replay, wrong product/amount/mode, unbound checkout and expired quote, email failure and retry, restart, two paid trips with different guidance, and wrong order/version cannot be attached. Separately demonstrate a real test checkout, real mailbox wake and the controlled final recipient before release.

- Set only on the pilot branch: `ARRIVAL_E2E=enabled`, `ARRIVAL_PREVIEW_DATABASE_URL`, `ARRIVAL_PREVIEW_TOKEN`, `ARRIVAL_CREEM_TEST_API_KEY`, `ARRIVAL_CREEM_TEST_WEBHOOK_SECRET`, and `ARRIVAL_PREVIEW_ORIGIN`. The operator route requires a secret bearer token and accepts only fixed fictional cases. Its webhook accepts only the dedicated Test signing secret and product. The Test webhook target must be reachable on an approved path without disabling deployment protection globally, and monitored from Creem.
- Operator starts a single checkout with POST /api/arrival-test (body `{"sample":0}`), pays with a test card and checks the **same** returned order ID via the authenticated GET. The webhook sends the verified owner mailbox an internal order-ID-only notice via the existing mail provider. Inspect real receipt plus connector wake. - **Not ready for live:** no catalog/live payment change, no publicly accepting customer intake, no real-input flight verification, no customer email sender or real dispatch path in this integration, and no customer/reviewer identity automation. The local rehearsal deliberately cannot authorize a production delivery. Confirm cashier → queue → mailbox wake → approved artifact → test recipient and refund/cancel handling before any live opening. The default-off route must serve 404 without config.

### Lost wake recovery

The authenticated operator GET without an ID lists paid orders even after the mail provider accepts the notification. This queue no longer treats notification acceptance as acknowledgement. POST with `{"claim":"ar_...","version":1}` acquires a 30-minute claim for that exact revision, atomically. Concurrent or stale claims return 409. Expired leases reappear in the list; the lease is not a fulfillment receipt. Never deliver twice based solely on this lease; a durable delivery receipt is still required.
